= CLASE 5: COMUNICACIÓN SERIAL ASINCRÓNICA Y PERIFÉRICO UART

== 1. Fundamentos de Comunicación Serial vs. Paralela
La transmisión de datos en sistemas embebidos se clasifica en dos arquitecturas fundamentales:

1. *Comunicación Paralela:*
   - Transmite múltiples bits en paralelo utilizando un bus dedicado de $n$ líneas de datos (8, 16, 32 bits) más líneas de control y reloj.
   - *Desventajas:* Requiere un alto número de pines físicos del microcontrolador, los cables son costosos y voluminosos, y sufre de desfasaje temporal (*skew*) entre líneas y acoplamiento capacitivo (*crosstalk*) a altas frecuencias, limitando su uso a distancias muy cortas.

2. *Comunicación Serial:*
   - Transmite los bits secuencialmente uno detrás de otro sobre un único canal o par de hilos ($"TX"$ y $"RX"$).
   - *Ventajas:* Mínimo uso de pines físicos, cableado sencillo y de bajo costo, alta inmunidad al ruido y posibilidad de alcanzar largas distancias.

=== Comunicación Sincrónica vs. Asincrónica
- *Sincrónica (SPI, I2C):* Existe una línea física explícita de reloj (*Clock*) provista por un máster para sincronizar la lectura de los bits en el emisor y receptor.
- *Asincrónica (UART):* No existe línea física de reloj. El emisor y el receptor acuerdan previamente una velocidad de transmisión fija (*Baud Rate*) y sincronizan sus relojes mediante el formato de una trama estructurada (*Start/Stop bits*).

=== Concepto de Bitrate vs. Baudrate
- *Bitrate (bits/s):* Velocidad neta de información digital transmitida por segundo.
- *Baudrate (símbolos/s):* Número de cambios de estado lógico o símbolos transmitidos por segundo sobre el medio físico. En UART binaria (2 niveles de tensión), $1 " símbolo" = 1 " bit"$, por lo que $"Bitrate" = "Baudrate"$.

=== Bit Banging vs. Periférico Dedicado por Hardware
- *Bit Banging:* Simulación de un puerto serie por software mediante la conmutación manual de pines GPIO con retardo por software. Consume valiosos ciclos de CPU y es altamente vulnerable a jitter provocado por interrupciones.
- *Periférico UART Dedicado:* Módulo de hardware integrado en el microcontrolador que realiza automáticamente la conversión paralelo-serie en transmisión y serie-paralelo en recepción mediante registros de desplazamiento (*Shift Registers*), liberando a la CPU.


== 2. Anatomía de la Trama UART (Protocolo 8N1)
La trama de datos UART estándar consta de los siguientes campos secuenciales:

1. *Línea en Reposo (Idle State):* Permanece en nivel lógico *ALTO (1 / $V_("DD")$)* de forma continua cuando no hay transmisión.
2. *Bit de Start:* Pulso en nivel *BAJO (0 / GND)* de duración exacta de 1 tiempo de bit ($T_("bit")$) que indica al receptor el inicio inminente de un dato.
3. *Carga Útil / Payload:* Datos transmitidos empezando por el bit menos significativo (*LSB primero*). Configurable entre 5 y 9 bits (el estándar industrial es de *8 bits*).
4. *Bit de Paridad (Opcional):* Bit de control de errores para detectar la alteración de un bit en la trama:
   - *Paridad Par (Even):* El bit se ajusta para que el total de unos en la trama sea par.
   - *Paridad Impar (Odd):* El bit se ajusta para que el total de unos sea impar.
   - *Sin Paridad (None - "N"):* Se omite este bit para maximizar el ancho de banda.
5. *Bit(s) de Stop:* Uno o dos bits en nivel *ALTO (1 / $V_("DD")$)* que marcan el cierre de la trama y retornan la línea al estado de reposo.

=== Cálculo de Eficiencia de Canal y Tiempo de Bit
Para el formato estándar *8N1* (8 bits de datos, Sin paridad, 1 bit de Stop):
- Total de bits por trama = $1 " Start" + 8 " Datos" + 0 " Paridad" + 1 " Stop" = 10 " bits"$.
- *Eficiencia del Canal:* 
  $"Eficiencia" = (8 " bits útiles")/(10 " bits totales") = 80 percent$
- *Tiempo de Bit ($T_("bit")$) a 9600 Baudios:*
  $T_("bit") = (1)/("Baud Rate") = (1)/(9600 " bps") approx 104.16   mu"s"$
  
=== Muestreo en Recepción y Tolerancia de Reloj
El receptor detecta el flanco descendente del bit de Start y sobremuestrea la señal $16times$ más rápido que el Baud Rate. Muestrea el nivel de tensión exactamente en el *centro teórico de cada bit ($0.5 times T_("bit")$)* para maximizar el margen de ruido.

*Tolerancia Máxima:* Dado que emisor y receptor poseen cristales independientes, un desfasaje acumulado mayor a *$2.5 percent$* entre ambos relojes hace que la muestra del último bit caiga fuera de ventana, provocando un error de alineación de trama (*Framing Error - FE*).


== 3. Capa Física y Estándares Eléctricos

=== Comparativa de Niveles Lógicos
- *TTL / CMOS:* Niveles lógicos directos del microcontrolador ($0"V" = "BAJO (0)"$, $3.3"V" / 5"V" = "ALTO (1)"$). Útil solo para conexiones dentro de la misma placa a corta distancia.
- *RS-232:* Estándar de transmisión bipolar para distancias de hasta 15 metros:
  - '0' Lógico (Space): $+3"V"$ a $+15"V"$.
  - '1' Lógico (Mark): $-3"V"$ a $-15"V"$.
  - Requiere un chip transceptor (como el *MAX232*) con bomba de carga para elevar las tensiones del microcontrolador.
  - Pinout DB9 estándar: Pin 2 (RXD), Pin 3 (TXD), Pin 5 (GND), Pin 7 (RTS), Pin 8 (CTS).

=== Adaptadores USB-Serial y OpenSDA en FRDM-K64F
- Chips adaptadores populares: FT232, CP2102, CH340.
- *OpenSDA:* La placa de desarrollo FRDM-K64F integra un microcontrolador secundario Kinetis que implementa el firmware OpenSDA. Este actúa como depurador JTAG/SWD y como puente USB-CDC (*Communications Device Class*), emulando un puerto COM virtual en la PC conectado internamente a los pines `PTB16` (UART0_RX) y `PTB17` (UART0_TX) de la `UART0` del K64F.

=== Control de Flujo por Software (XON / XOFF)
Utilizado para evitar que el receptor sea desbordado en ausencia de líneas físicas de control de flujo (RTS/CTS):
- *XOFF (`0x13` / Ctrl+S):* El receptor envía este carácter para pedir al emisor que pause la transmisión al alcanzar la marca de agua superior del buffer.
- *XON (`0x11` / Ctrl+Q):* El receptor lo envía para reanudar la transmisión tras vaciar el buffer.


== 4. Mapeo de Registros y Configuración en Kinetis K64F

=== Asignación de Relojes a las UARTs en K64F
El microcontrolador Kinetis K64F posee 6 módulos UART independientes (`UART0` a `UART5`):
- `UART0` y `UART1`: Se alimentan del *System Clock* ($f_("core")$ hasta 100 MHz).
- `UART2`, `UART3`, `UART4` y `UART5`: Se alimentan del *Bus Clock* ($f_("bus")$ hasta 50 MHz).

=== System Clock Gating Control
Antes de acceder a cualquier registro de la UART, es obligatorio activar el reloj del periférico:
```c
// UART0, UART1, UART2, UART3 están en SIM->SCGC4
SIM->SCGC4 |= SIM_SCGC4_UART0_MASK;

// UART4 y UART5 están en SIM->SCGC1
SIM->SCGC1 |= SIM_SCGC1_UART4_MASK;
```

=== Configuración del MUX de Pines
Para multiplexar los pines del Puerto B hacia la `UART0`:
```c
// PTB16 = UART0_RX (ALT3), PTB17 = UART0_TX (ALT3)
PORTB->PCR[16] = PORT_PCR_MUX(3); 
PORTB->PCR[17] = PORT_PCR_MUX(3);
```

=== Fórmula Matemática de Baud Rate con Ajuste Fino
La UART de Kinetis K64F utiliza un divisor de reloj de 13 bits para el *ajuste grueso ($"SBR"$)* y un registro de 5 bits para el *ajuste fino fraccionario ($"BRFA"$)*:

$"Baud Rate" = ("UART_CLK")/(16 times <="ft"("SBR" + ("BRFA")/(32)))$

1. *Modulo Baud Rate Register ($"SBR"$):*
   - Registro de 13 bits compuesto por `UARTx->BDH` (bits [4:0]) y `UARTx->BDL` (bits [7:0]).
   - Cálculo del divisor grueso: $"SBR" = "floor"<="ft"(("UART_CLK")/(16 times "Baud Rate"))$.
2. *Baud Rate Fine Adjust ($"BRFA"$):*
   - Bits [4:0] del registro `UARTx->C4`.
   - Modula el divisor dividiendo el residuo decimal por 32 para lograr un error de baud rate inferior al 0.5%:
     $"BRFA" = "round"<="ft"(<="ft"(("UART_CLK")/(16 times "Baud Rate") - "SBR") times 32)$

==== Función de Configuración de Baud Rate en C:
```c
void UART_SetBaudRate(UART_Type *uart, uint32_t baudrate) {
    uint16_t sbr;
    uint8_t brfa;
    uint32_t clock;

    // Determinar la fuente de reloj según el módulo
    clock = ((uart == UART0) || (uart == UART1)) ? SystemCoreClock : (SystemCoreClock / 2);

    // Calcular divisor grueso y ajuste fino
    sbr = clock / (baudrate << 4);
    brfa = (uint8_t)(((clock << 1) / baudrate) - (sbr << 5));

    // Escribir en registros (Guardando configuración previa)
    uart->BDH = (uart->BDH & ~UART_BDH_SBR_MASK) | UART_BDH_SBR(sbr >> 8);
    uart->BDL = UART_BDL_SBR(sbr);
    uart->C4 = (uart->C4 & ~UART_C4_BRFA_MASK) | UART_C4_BRFA(brfa);
}
```


== 5. Registros de Datos, Estado y Control (`UART_Type`)

=== Principales Registros del Módulo:
- `UARTx->D` (Data Register): Contiene dos buffers físicos separados. Escribir en `D` coloca un byte en el buffer de transmisión; leer `D` extrae el byte recibido del buffer de recepción.
- `UARTx->S1` (Status Register 1):
  - *`TDRE` (Bit 7 - Transmit Data Register Empty):* Indica que el registro de transmisión está libre para aceptar un nuevo byte ($1 = "Vacío"$).
  - *`TC` (Bit 6 - Transmission Complete):* Indica que la transmisión ha finalizado por completo y el último bit ya salió físicamente del pin TX.
  - *`RDRF` (Bit 5 - Receive Data Register Full):* Indica que ha ingresado un byte completo al registro de recepción ($1 = "Lleno"$).
  - *`OR` (Bit 3 - Receiver Overrun):* Indica que se recibió un byte nuevo antes de haber leído el anterior, perdiéndose datos.
  - *`FE` (Bit 1 - Framing Error):* Error de trama/stop bit.
  - *`PF` (Bit 0 - Parity Error):* Error de paridad.
- `UARTx->C2` (Control Register 2):
  - *`TIE` (Bit 7):* Habilita interrupción por registro de transmisión vacío (`TDRE`).
  - *`TCIE` (Bit 6):* Habilita interrupción por transmisión completa (`TC`).
  - *`RIE` (Bit 5):* Habilita interrupción por recepción llena (`RDRF`).
  - *`TE` (Bit 3):* Habilita el módulo Transmisor.
  - *`RE` (Bit 2):* Habilita el módulo Receptor.

=== REGLA DE ORO: Secuencia de Doble Lectura para Limpiar Banderas
Para limpiar las banderas de estado `TDRE` y `RDRF` en el K64F, el hardware exige ejecutar una secuencia estricta de dos pasos:
1. *1º Paso:* Leer el registro de estado `UARTx->S1`.
2. *2º Paso:* Leer o escribir el registro de datos `UARTx->D`.
*Si se omite el primer paso o se intenta limpiar escribiendo directamente en S1, la bandera continuará activa y el microcontrolador quedará atrapado en un bucle infinito de interrupciones.*


== 6. Buffers de Hardware (FIFOs) y Marcas de Agua (Watermarks)
Además de los registros simples, las UARTs de Kinetis K64F disponen de FIFOs de hardware de tamaño programable ($2^("SIZE")$ bytes: 1, 4, 8, 16, 32, 64, 128 datawords):

- `UARTx->PFIFO`:
  - `TXFE` (Bit 7) / `RXFE` (Bit 3): Habilitan las FIFOs de transmisión y recepción.
  - `TXFIFOSIZE` (Bits [6:4]) / `RXFIFOSIZE` (Bits [2:0]): Leen la capacidad física de hardware soportada por el chip.
- `UARTx->CFIFO`:
  - `TXFLUSH` (Bit 7) / `RXFLUSH` (Bit 6): Limpian e inicializan a cero las colas FIFO de TX/RX.
- `UARTx->TWFIFO` / `UARTx->RWFIFO` (Watermark Registers):
  - *`TXWATER`:* Genera interrupción `TDRE` cuando el número de bytes cargados en la FIFO de transmisión sea $<= "TXWATER"$.
  - *`RXWATER`:* Genera interrupción `RDRF` cuando el número de bytes acumulados en la FIFO de recepción sea $>= "RXWATER"$.
- `UARTx->TCFIFO` / `UARTx->RCFIFO`: Contadores de lectura en tiempo real del número de bytes alojados actualmente en cada FIFO.


== 7. Arquitectura de Firmware, Ring Buffers e ISR Compartida

=== Asimetría Temporal y Colas Circulares (*Ring Buffers*)
La transmisión y recepción de datos por UART operan a tiempos enormemente lentos comparados con la velocidad de la CPU ($1 " byte a " 9600 " baudios" approx 1.04 " ms" = 104,160 " ciclos de CPU"$). Por ello:
- *Recepción (RX):* Es altamente crítica. Si la CPU no retira inmediatamente el byte al recibirlo, el siguiente byte lo pisará provocando un error de desbordamiento (*Overrun Error*).
- *Transmisión (TX):* No pierde datos si la CPU se demora, pero genera bloqueos inaceptables si se espera la salida de cada byte por software.

*Solución:* Implementar *Colas Circulares (*Ring Buffers*)* en memoria RAM atendidas por interrupciones.

=== Implementación Típica de Ring Buffer en C
```c
#define RING_BUFFER_SIZE 128

typedef struct {
    uint8_t buffer[RING_BUFFER_SIZE];
    volatile uint16_t in;
    volatile uint16_t out;
    volatile uint16_t count;
} RingBuffer_t;

void RingBuffer_Init(RingBuffer_t *rb) {
    rb->in = 0;
    rb->out = 0;
    rb->count = 0;
}

bool RingBuffer_Put(RingBuffer_t *rb, uint8_t data) {
    if (rb->count >= RING_BUFFER_SIZE) return false; // Buffer Lleno
    rb->buffer[rb->in] = data;
    rb->in = (rb->in + 1) % RING_BUFFER_SIZE;
    rb->count++;
    return true;
}

bool RingBuffer_Get(RingBuffer_t *rb, uint8_t *data) {
    if (rb->count == 0) return false; // Buffer Vacío
    *data = rb->buffer[rb->out];
    rb->out = (rb->out + 1) % RING_BUFFER_SIZE;
    rb->count--;
    return true;
}
```

=== Rutina de Interrupción Compartida RX/TX (`UART0_RX_TX_IRQHandler`)
En el K64F, la recepción y la transmisión del mismo canal UART comparten el mismo vector en la IVT (`UART0_RX_TX_IRQn`). La ISR consulta `S1` para atender ambas fuentes:

```c
RingBuffer_t rx_buffer;
RingBuffer_t tx_buffer;

void UART0_RX_TX_IRQHandler(void) {
    uint8_t status = UART0->S1; // 1. Lectura obligatoria de S1 para secuencia de borrado

    // A) Atender Recepción (RDRF = 1)
    if (status & UART_S1_RDRF_MASK) {
        uint8_t byte_recibido = UART0->D; // 2. Lectura de D limpia el flag RDRF de forma atómica
        RingBuffer_Put(&rx_buffer, byte_recibido);
    }

    // B) Atender Transmisión (TDRE = 1 y TIE Habilitado)
    if ((status & UART_S1_TDRE_MASK) && (UART0->C2 & UART_C2_TIE_MASK)) {
        uint8_t byte_a_enviar;
        if (RingBuffer_Get(&tx_buffer, &byte_a_enviar)) {
            UART0->D = byte_a_enviar; // 2. Escritura en D limpia el flag TDRE
        } else {
            // Si la cola de transmisión quedó vacía, deshabilitar interrupción TIE 
            // para evitar un bucle infinito de IRQs
            UART0->C2 &= ~UART_C2_TIE_MASK;
        }
    }
}
```
